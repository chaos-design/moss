# Moss 平台计划中心

本目录保存当前仓库的审计结论、实施计划、待决事项和历史基线。目录名 `planing` 沿用任务要求，
表示已经完成技术拆解、可以进入实施的工作。

## 状态目录

| 目录 | 含义 | 进入条件 | 离开条件 |
| --- | --- | --- | --- |
| [`planing`](planing/) | 已完成设计和拆解，可按依赖顺序实施 | 范围、方案、测试和 DoD 明确 | 完成后移入 `archive`；失去前置条件时移入 `pending` |
| [`pending`](pending/) | 需要产品、安全、发布或平台决策 | 存在无法由代码单独决定的约束 | 决策完成并补齐 DoD 后移入 `planing` |
| [`archive`](archive/) | 已完成的审计、验证基线和历史计划 | 结论已固化或任务已完成 | 只做勘误，不继续追加实施任务 |

## 优先级

| 级别 | 定义 | 处理要求 |
| --- | --- | --- |
| P0 | 可造成越界访问、凭据泄漏、错误工作区写入或不可控破坏 | 在新增能力前处理 |
| P1 | 核心功能不可达、恢复语义不完整、并发写不可靠或门禁失效 | 在首个稳定版本前处理 |
| P2 | 性能、可维护性、扩展性或开发体验问题 | 在 P0/P1 收敛后处理 |

## 统一完成标准

每个实施任务必须同时满足：

1. `code`：实现、迁移和文档均已完成，不保留双轨逻辑。
2. `linter_result`：`corepack pnpm lint` 退出码为 0。
3. `unit_test_result`：新增边界测试通过，关键包覆盖率不低于 90%。
4. `func_test_result`：对应的 CLI、Session、工具或安全场景完成真实进程验证。
5. `status`：任务状态、剩余风险和回滚方式已记录，完成项移入 `archive`。

## 变更原则

- 不用全局可变状态传递 Session、Workspace、权限或凭据。
- 所有文件路径都经过真实路径边界校验；符号链接默认不能越出工作区。
- 所有写操作都进入统一写协调器，并在执行前后留下可恢复记录。
- Shell 不是工作区边界的例外；环境变量、网络、目录和危险动作都必须受策略约束。
- 非交互模式必须显式获得预授权，不能通过跳过授权界面获得写能力。
- `index.ts` 只导出，包间只使用相对源码导入和公开 package export。
- 不创建 Git 提交；版本基线由仓库维护者在外部流程中处理。
